A probability distribution is usually introduced as a formula and remembered as a silhouette. That is a poor way to learn one. The useful question is not only “what is the density?” It is: what does the density look like, what samples does it produce, what parameters control it, and does it describe the data in front of me?

I built **probviz** to keep those questions together. It is a typed Python library and a Streamlit explorer for probability distributions, sampling, fitting, dependence, Monte Carlo, and statistical tests. It is now published on [PyPI](https://pypi.org/project/probviz/), with [source on GitHub](https://github.com/sanskarpan/probviz) and [documentation on GitHub Pages](https://sanskarpan.github.io/probviz/).

The shortest way to try it is deliberately short:

```bash
pip install probviz
probviz app
```

The app starts on port `8501`. For the test extras:

```bash
pip install "probviz[test]"
probviz test
```

That second command runs the same suite that protects the release. The current package is `probviz 1.0.3` and the suite contains 694 passing tests across Python 3.10, 3.11, and 3.12.

## Start with a shape, not a formula

The first thing the app should do is make a parameter feel physical. Increase the standard deviation of a normal distribution and the curve gets wider and lower. Decrease it and probability gathers around the mean. The formula has not changed; the relationship between its parameters and its shape has become visible.

## Sixteen distributions, one contract

The library starts with 16 univariate distributions: 10 continuous and 6 discrete. Each is a small validated wrapper around a frozen SciPy distribution. The wrapper gives them the same useful vocabulary: `pdf`, `cdf`, `ppf`, `rvs`, `mean`, `var`, `median`, `mode`, `entropy`, `support`, and `interval`.

```python
from src.distributions.continuous import NormalDistribution

normal = NormalDistribution(mu=0, sigma=1)

print(normal.pdf(0))
print(normal.cdf(1.96))
print(normal.ppf(0.5))
print(normal.rvs(size=1_000, random_state=0).mean())
```

The parameter layer matters as much as the plotting layer. A slider must not be able to create `sigma = 0`, an invalid beta shape, or a uniform distribution whose upper endpoint comes before its lower endpoint. Every class exposes `get_parameters()`, `get_parameter_bounds()`, and `set_parameters()` so the app can build its controls from the distribution itself rather than maintaining a second, drifting registry of rules.

The continuous set is Normal, Exponential, Uniform, Beta, Gamma, Chi-Square, Student-t, Weibull, Lognormal, and Cauchy. The discrete set is Binomial, Poisson, Geometric, Negative Binomial, Hypergeometric, and Discrete Uniform. A discrete distribution's `pdf` dispatches to its PMF, so the public call still works while the plot can use bars instead of pretending a count distribution is smooth.

## Shape has more than one parameter

The beta distribution is a good test of whether a visualizer is doing anything useful. Its support stays fixed at the interval from zero to one, but its two shape parameters can produce a uniform-looking curve, a central peak, a skewed tail, or mass pressed against a boundary.

This is also why the app keeps statistics beside the plot. A curve can look “more concentrated” while its mean stays fixed, or move its mean while its variance changes in a less obvious way. The app renders mean, variance, standard deviation, median, mode, skewness, and excess kurtosis together, then exposes quantiles through `ppf`.

## Sampling is where the picture gets tested

The curve is theoretical. A sample is noisy. The central limit theorem is the bridge between them: take independent observations with finite variance, average more of them, and the distribution of those averages approaches a normal law.

<Figure label="Fig 3" caption="The central limit effect: individual samples remain noisy, while the distribution of their means settles into a normal shape as the sample size grows.">
  <img class="probviz-gif" src="/probviz/clt_convergence.gif" alt="Animated histograms showing sample means converging toward a normal distribution" width="720" height="405" loading="lazy" />
</Figure>

The library keeps random generation explicit and reproducible:

```python
from src.distributions.continuous import GammaDistribution

gamma = GammaDistribution(shape=2, scale=2)
sample = gamma.rvs(size=10_000, random_state=7)

print(sample.mean())
print(gamma.mean())
```

The `random_state` belongs to the call. Sampling one distribution should not silently reseed a different part of a notebook or test process. That local-RNG rule was one of the changes made during the production audit: copulas, mixture fitting, and multivariate samplers use local generators rather than mutating NumPy's global random state.

## Dependence is invisible in a marginal

Two variables can have perfectly ordinary one-dimensional distributions and still have an interesting joint structure. A scatter plot reveals that structure, but a pair of marginals does not. Copulas provide a way to model the dependence separately from the marginals.

<Figure label="Fig 4" caption="A Gaussian copula changes the dependence between uniform marginals while keeping each marginal uniform. The colour and point cloud make correlation visible.">
  <img class="probviz-gif" src="/probviz/copula_dependence.gif" alt="Animated copula samples changing from weak to strong dependence" width="720" height="405" loading="lazy" />
</Figure>

The fitting path is rank-based: turn observations into pseudo-observations, estimate dependence, then sample in the unit square. In mathematical form, the Gaussian copula density is:

<div class="equation" role="img" aria-label="The Gaussian copula density using a correlation matrix Sigma">
  <math display="block">
    <mi>c</mi><mo>(</mo><mi>u</mi><mo>)</mo><mo>=</mo>
    <mfrac>
      <mn>1</mn>
      <msqrt><mo>|</mo><mi>Σ</mi><mo>|</mo></msqrt>
    </mfrac>
    <msup><mi>e</mi><mrow><mo>−</mo><mfrac><mn>1</mn><mn>2</mn></mfrac><msup><mi>z</mi><mi>T</mi></msup><mo>(</mo><msup><mi>Σ</mi><mrow><mo>−</mo><mn>1</mn></mrow></msup><mo>−</mo><mi>I</mi><mo>)</mo><mi>z</mi></mrow></msup>
  </math>
  <span class="equation__caption">Here z is the component-wise normal quantile of u.</span>
</div>

```python
import numpy as np
from src.distributions.copulas import GaussianCopula

correlation = np.array([[1.0, 0.75], [0.75, 1.0]])
copula = GaussianCopula(correlation=correlation)

u = copula.rvs(n_samples=2_000, random_state=0)
print(u.shape)
print(u.min(), u.max())
```

probviz includes Gaussian, Clayton, Gumbel, and Student-t copulas. The limitations are intentional and visible in the API: Clayton and Gumbel density and sampling methods are bivariate-only; the Student-t copula exposes sampling while its density and CDF explicitly direct users toward Monte Carlo. A limitation that raises clearly is more useful than an implementation that returns a plausible-looking wrong answer.

## Mixtures: when one curve is not enough

If a dataset contains two populations, fitting one normal distribution can hide the structure. A mixture represents several component distributions and weights their densities:

  <img class="probviz-gif" src="/probviz/mixture_separation.gif" alt="Animated Gaussian mixture components separating into two peaks" width="720" height="405" loading="lazy" />

The implementation includes a one-dimensional EM fitter, a scikit-learn Gaussian-mixture wrapper, Bayesian GMM, and BIC-based component selection. The EM implementation is guarded at the places where numerical examples usually become production bugs: empty data, too many components, zero row likelihoods, zero component counts, and zero variance. Most importantly, convergence is checked after the M-step, so the returned parameters describe the likelihood value that actually converged.

```python
import numpy as np
from src.distributions.mixtures import GaussianMixtureModel

rng = np.random.default_rng(4)
data = np.concatenate([
    rng.normal(-2, 0.6, 300),
    rng.normal(2, 0.8, 300),
])

model = GaussianMixtureModel(n_components=2)
model.fit(data)

print(model.get_parameters())
print(model.bic(data))
```

The distinction between the hand-written EM path and the sklearn model is useful. The first makes the algorithm and its failure modes inspectable. The second gives a production-grade multivariate estimator. They share the same idea, not the same abstraction.

## From a picture back to data

Visualization becomes analysis when it can answer “which model describes this sample?” `DistributionFitter` tries ten candidate laws — normal, exponential, gamma, beta, lognormal, Weibull, Student-t, chi-square, uniform, and Cauchy — using maximum likelihood. It reports log likelihood, AIC, BIC, and a KS statistic, then sorts the results by AIC.

```python
import numpy as np
from src.fitting.distribution_fitter import DistributionFitter

data = np.random.default_rng(12).gamma(shape=2, scale=2, size=500)
fitted = DistributionFitter(data).fit_all()

best_name, best_result = next(iter(fitted.items()))
print(best_name)
print(best_result["aic"], best_result["bic"])
```

The output is a regular dictionary instead of an opaque library-specific result object. That makes it easy to log, serialize, compare, or put behind an API. `BayesianEstimator` adds conjugate updates for normal means and variances, Poisson rates, and Bernoulli probabilities. `GoodnessOfFit` wraps chi-square, KS, Anderson-Darling, Shapiro-Wilk, and Jarque-Bera tests.

## Monte Carlo is an uncertainty tool

Monte Carlo is often introduced as “draw many samples and average them.” The average is only half the answer. The other half is how uncertain that estimate is and how quickly it stabilises. `MonteCarloSimulator` returns samples, summary statistics, quantiles, a confidence interval, and optional convergence data. Its probability estimator uses a Wilson interval rather than a symmetric interval that can wander below zero or above one.

The library also includes importance sampling, stratified sampling, bootstrap, permutation tests, antithetic variates, control variates, Halton sequences, and Sobol sequences. The expectation formula is simple:

<div class="equation" role="img" aria-label="The Monte Carlo estimate of an expectation is the average of function values">
  <math display="block">
    <mover><mi>E</mi><mo>^</mo></mover><mo>[</mo><mi>g</mi><mo>(</mo><mi>X</mi><mo>)</mo><mo>]</mo><mo>=</mo>
    <mfrac><mn>1</mn><mi>n</mi></mfrac>
    <munderover><mo>∑</mo><mrow><mi>i</mi><mo>=</mo><mn>1</mn></mrow><mi>n</mi></munderover>
    <mi>g</mi><mo>(</mo><msub><mi>X</mi><mi>i</mi></msub><mo>)</mo>
  </math>
  <span class="equation__caption">More samples reduce noise, but variance reduction can reduce the noise per sample.</span>
</div>

```python
from src.monte_carlo.simulator import MonteCarloSimulator

simulator = MonteCarloSimulator(random_seed=0)
result = simulator.simulate(
    lambda: np.random.normal(),
    num_samples=10_000,
    track_convergence=True,
)

print(result.mean)
print(result.confidence_interval)
```

The private `_rng` in that small example is only there to make the source of randomness explicit. In application code, pass a public random function or distribution sampler. The important point is that an estimate should arrive with its uncertainty, not just a number with too many decimal places.

## The app is a laboratory, not a dashboard

The Streamlit app is deliberately one page with a sidebar. The sidebar chooses continuous or discrete distributions, creates parameter controls from the distribution's own bounds, and exposes PDF/PMF, CDF, and sample toggles. The main page places statistics, plots, quantiles, and an optional sample histogram beside one another.

That layout is intentional. A dashboard encourages scanning. A laboratory encourages changing one thing and watching what responds. Move a parameter, compare the curve with its CDF, turn on samples, and then ask whether the empirical mean and quantiles are behaving as the theory predicts.

The app covers the 16 univariate distributions. The advanced modules remain a Python API: multivariate distributions, copulas, mixtures, fitting, Monte Carlo, and statistical tests. That boundary is documented rather than hidden behind half-finished UI controls.

For notebooks and applications, the visualizer functions return figures instead of displaying them:

```python
from src.distributions.continuous import NormalDistribution
from src.visualizers import plot_cdf, plot_comparison, plot_pdf

normal = NormalDistribution(mu=0, sigma=1)
fig, ax = plot_pdf(normal)
fig, ax = plot_cdf(normal, num_points=250)
fig, ax = plot_comparison([normal, NormalDistribution(mu=1, sigma=0.8)])
```

No helper calls `plt.show()`. You can embed the returned figure, add annotations, save it, or close it when a web request is finished.

## Try the whole loop

Install the library:

```bash
pip install probviz
```

Open the explorer:

```bash
probviz app --server.port 8501
```

Use the API from a notebook or script:

```python
import numpy as np
from src.distributions.continuous import GammaDistribution
from src.fitting.distribution_fitter import DistributionFitter

distribution = GammaDistribution(shape=2, scale=2)
observations = distribution.rvs(size=200, random_state=0)

print("theoretical mean:", distribution.mean())
print("sample mean:", observations.mean())

fits = DistributionFitter(observations).fit_all()
print("best candidate:", next(iter(fits)))
```

Then install the test extras and run the fixtures yourself:

```bash

```

The project is not a replacement for SciPy, and the Streamlit page is not a general-purpose statistical workbench. It is a coherent surface over a set of probability ideas that are usually separated: distributions, dependence, samples, fitting, uncertainty, and tests. Its value is the connection between them.

The thesis is simple: a distribution should be something you can see, perturb, sample from, fit, and question. That is what I tried to make `probviz` — a library you can import, an app you can drag, and a set of figures that make the mathematics harder to misunderstand.

The [package is on PyPI](https://pypi.org/project/probviz/), the [source is on GitHub](https://github.com/sanskarpan/probviz), and the [API documentation is live](https://sanskarpan.github.io/probviz/). Start with `pip install probviz`, move a slider, and see whether the picture agrees with the formula.
